# 设计

> 状态：脚手架阶段。范围与关键取舍已定，实现随里程碑推进。

## 目标

把 DSH 的会话数据在自有服务端上做**多设备同步**，默认端到端加密；服务端只保存不透明密文与元数据。

## 数据分三层

| 层 | 内容 | 体量量级 | 冲突性 |
|---|---|---|---|
| L1 会话数据 | `sessions/**`（每会话只取最高格式代际）、`attachments/v1/**`、`storages/workspace.json`、`profiles/*/cordis.patch.yml` + `package.json` | 百 MB 级（取决于历史） | 会话要租约；配置字段级 LWW |
| L2 设备台账 | 每设备一条：OS、DSH 与 profile、已加载插件与版本、会话格式版本、工具链版本与路径、工作区路径、最后在线 | KB 级 | 按 deviceId 分槽，天然无冲突 |
| L3 agent 笔记 | append-only 笔记：设备/会话/工作区/时间/作者/标签 | KB–MB 级 | 只追加，天然无冲突 |

L2 同时是**兼容性闸门**：服务端一次性返回各设备的 `sessionFormatVersion`，同步前就能拒绝代际不匹配的会话。
L3 的工具链条目分 `auto`（自动采集）与 `authored`（agent 或用户维护）两个来源，自动采集**不覆盖** `authored`。

## 传输单位：zstd 帧链

DSH 的会话日志是一串独立 zstd 帧：header 一帧，之后每个持久化批次一帧。已提交帧不可变，只有尾帧可能被崩溃恢复重写。

因此同步单位是**原始帧**：不解码、不重编码、sha256 内容寻址。好处是增量天然成立，而且传输层不可能产出 DSH 读不了的日志。附件本身按 digest 命名，直接按内容寻址同步。

### 帧到底是什么（实测一条会话）

一条 v4 日志 = header 帧 + N 个追加帧的拼接。实测一条 160 KB 的会话有 **125 帧**：帧 0 是 header（1 行），其余帧多为 1–9 行（例如一帧就是 `step/start … request/context` 一整批）。

要点：

- **一帧不等于一轮/一步**：帧只是“这一次落盘写了哪些事件”的物理边界，一条多轮会话会攒出上百帧；
- 帧之间独立压缩，可按 zstd magic 边界切分，无需解压全文；
- 已提交帧不可变，只有最后一帧可能被崩溃恢复重写。

同步时从 `f0` 起逐帧比较哈希：哈希相同的连续前缀是**公共前缀**，只搬运缺失的尾帧；第一个不同帧意味着**分叉**，不能直接拼接（`seq` 会重复/错乱），保留双方人工处理。

### 两种哈希

- **链身份**用明文帧的哈希：同一帧换密钥加密后字节不同，不能拿来比对；
- **服务端去重**用密文哈希：服务端只看到密文，按存储字节寻址。

因此会话 manifest 同时记录两种标识：明文 `chainHash`（比对/分叉判定）与密文 `blobSha256`（取数据/去重）。

## 并发：会话级租约

DSH 的单写者锁只在一台机器内生效，跨机器不拦。服务端按会话发租约：拿到租约才能追加帧；两台同时写同一会话时先到者胜，后来者收到 `409`。

**分叉不自动合并**：`seq`/`surfaceOp`/`sourceEventSeqs` 是格式拥有的关系，重排它们会产出 DSH 读不了的日志。分叉时保留双方，供人工取回。

## 拉取后如何生效

优先走 DSH 原生接缝——`ctx.sessionPersistence` 写入、`ctx.workspaceRegistry.resolveByPath` + `Workspace.attachSession` 挂回工作区，避免重启宿主。该路径能否让**已打开的客户端**立即看到，是 M0 实验要回答的问题；做不到才回退为提示重启。

## 换设备与设备标记

会话在不同设备间继续时，模型需要知道"自己换机器了"。做法：

- 在会话日志里写一条 `plugin:dsh-session-sync/device` 记录（`ignorable`，不进模型可见表面）；
- 用 Session projection 折叠出"最后设备"（不扫历史，`snapshotEvents` 已弃用）；
- 判定为换设备时，在 `agent/pre-step` 追加一条 `<system-reminder>`（最小事实 + 该工作区 agent 笔记摘要），不唤醒会话。

## 加密

默认端到端：口令派生主密钥，按会话派生子密钥，AES-256-GCM 封装每一帧。服务端只知道账户、设备、加密后的会话键、大小与时间。提供一个显式开关"允许服务器解密"（上传包裹后的主密钥），默认关闭；关闭时必须配套密钥轮换，否则旧密文仍可被解开。

封帧的字节布局、密钥层次、AAD 与版本规则见 [SEALED-FRAME.md](./SEALED-FRAME.md)（v1 已实现）。

## 服务器形态

本期只做**个人自部署**：单租户、无账号/邮箱，认证是 setup token + 每设备 token。为将来可能的公共部署只保留两个薄接缝：存储的 `dataset` 字段、token 表的 `label`。

## 网页管理台（首版）

自部署服务附带一个只读管理台：浏览器用 setup token 登录，换取 **HttpOnly cookie 会话**；设备 API 仍用 bearer token。管理台**不依赖服务器解密**（默认关闭），首版只做元数据管理：

- 设备 token：签发 / 吊销 / 最后在线；
- 存储：总用量、配额（默认 10 GiB，`--max-bytes` 可配）、按会话统计；
- 会话：id、格式代际、帧数、最后更新、租约持有者、墓碑；
- 系统：健康、协议版本、keybox 状态。

会话内容预览（网页读消息/工具/推理）是 **P2**，依赖“允许服务器解密”：开启后服务端能解**所有历史帧**；删除 keybox 不等于收回历史，必须轮换密钥，UI 必须明确警告。

同步 API（`/v1/*`，设备 token）与管理台 API（`/admin/*`，cookie 会话）分开，互不复用认证。

## 首次启动与初始化

服务端首次启动（尚未设置管理密码）时，在控制台打印一次性初始化密钥，并提示打开 `/admin`；浏览器跳到 `/setup` 向导：

1. 输入初始化密钥（8 位、10 分钟有效、单次使用；未完成初始化时每次启动重新生成）；
2. 设置管理密码（≥6 位，字母/数字/特殊字符至少两类；scrypt 加盐哈希，不存明文）；
3. 设置存储配额（默认 10 GiB，之后可在管理台修改）；
4. 可选创建第一台设备（token 只显示一次，可跳过）。

完成后管理台改用密码登录；setup token 只保留给设备 CLI 和 break-glass。忘记密码时执行 `admin reset` 清除密码，重启后重新打印初始化密钥。

## 版本策略

只支持 DSH `>=0.2.1-rc.1 <0.2.2-0`。用**特性探测**而非版本比较；缺必需 API 时装载期报错并给出所需版本。不维护旧版本兼容分支。

## 兼容性边界

同步层按帧搬运字节、不解码事件，所以**事件 schema 的增删不需要改同步代码**；但"不受影响"只对同一格式代际成立：

- **同一代际**（如 v4）：未知事件由 DSH 自己 fail-closed（非 `ignorable` 的事件会被拒绝读取），我们照搬字节；
- **跨代际**（v4 → v5）：旧 DSH 直接拒读（`sessionFormatVersionRefusal`），同步必须按 `formatVersion` 闸门，不把新代际日志推给旧设备；manifest 与会话台账都记录代际，同步前可预判；
- **同代际但 DSH 版本不同**：新补丁若引入非 `ignorable` 事件，旧版本仍会拒读；设备台账比较 DSH 版本，默认只向不低于自己的设备推送；
- **依赖的格式假设**：只有尾帧可能被崩溃恢复重写；目录布局与压缩参数由 `sessionPersistence` 抽象，不自己拼路径——这些假设若变，需要跟着适配；
- **插件 API**：`appendPluginRecord` 等只在 `>=0.2.1 <0.2.2` 内验证，越过这个小版本要重新验证；官方校验器随 DSH 升级同步升版本并重跑夹具。

## 非目标

- 不做事件级合并（不重排 `seq`/`surfaceOp`）。
- 不做服务端合并（端到端加密下服务端看不到明文）。
- 不自动重启宿主。
- 第一版不同步工作区项目文件。
