# 设计

> 状态：M1/M2 已落地；M3 传输模型已定为事件批次并已实现；M4 客户端防护做收口。
> L2/L3 的加密附加数据层与多工作区映射见 [VAULT.md](VAULT.md)（设计稿）。

## 目标

把 DSH 的会话数据在自有服务端上做**多设备同步**，默认端到端加密；服务端只保存不透明密文与元数据。

## 数据分三层

| 层 | 内容 | 体量量级 | 冲突性 |
|---|---|---|---|
| L1 会话数据 | `sessions/**`（每会话只取最高格式代际）、`attachments/v1/**`、`storages/workspace.json`、`profiles/*/cordis.patch.yml` + `package.json` | 百 MB 级（取决于历史） | 会话要租约；配置字段级 LWW |
| L2 设备台账 | 每设备一条：OS、DSH 与 profile、已加载插件与版本、会话格式版本、工具链版本与路径、工作区路径、最后在线 | KB 级 | 按 deviceId 分槽，天然无冲突 |
| L3 agent 笔记 | append-only 笔记：设备/会话/工作区/时间/作者/标签 | KB–MB 级 | 只追加，天然无冲突 |

L2 同时是**兼容性闸门**：服务端只返回各设备的加密台账，客户端解密后拿到 `sessionFormatVersion`，
在同步前拒绝代际不匹配的会话。
L2 的工具链条目分 `auto`（自动采集）与 `authored`（agent 或用户维护）两个来源，自动采集**不覆盖** `authored`。
L2/L3 的加密存储、工作区 key 与绑定、插件版本匹配见 [VAULT.md](VAULT.md)。

## 传输单位：事件批次

DSH 公开的持久化接口是**事件级**的：`SessionHandle.read()` 返回校验过的事件数组，`append(events)` 由 DSH 自己编码落盘；没有读取或追加原始帧字节的入口。物理帧边界（zstd 帧、压缩参数、`compression: 'none'` 的纯文本行）属于存储实现，不能作为同步契约。

因此同步单位是**连续事件批次**：

- 一批 = `[seqFrom, seqTo]` 的连续事件，由写入方在同步时封口，默认上限 **50 个事件或 256 KiB**（可调）；
- 批次上传后**不可变**，新事件只能进新批次；只有尚未上传的开放尾批可以继续追加或替换；
- 链身份 = 批次规范 JSON（键序稳定）的 sha256；服务端去重 = 封装后密文的 sha256；
- 拉取方**不重新切批**：以服务端 manifest 的批次范围为准，逐批比较哈希。

### 为什么不用帧

一条 160 KB 的 v4 日志实测有 **125 帧、261 个事件**（约 2.1 事件/帧，单帧 82 B–14 KB）。帧级方案的问题：

- 帧边界由 DSH 的落盘策略决定，不是稳定契约；`compression: 'none'` 时甚至没有帧；
- header 帧含 `cwd`；若各设备用本地路径，header 帧哈希不同，两台设备的链从第 0 帧就分叉；
- 一帧可能含多个事件，按帧截断/删除会连带丢掉同帧的好事件；
- 直接读写文件会绕过 DSH 的校验、锁与可见性。

事件级把 header 留作带外元数据，链从第一个事件批次开始；同一会话 id 不变，事件里的 `sessionId` 引用自然成立。

### 批次对齐与部分重叠

- **第一个推送者定义边界**；manifest 中的 `[seqFrom, seqTo]` 是权威，其他设备只按它验证/补齐；
- 本地已有完整前缀批次：只算哈希，不下载；
- 批次跨过本地末尾：下载该批，校验重叠段与本地一致，只追加缺的后半段；
- 例：A 到 150、B 在 65 时是副本；A 先推 `B0 0..49`、`B1 50..99`、`B2 100..149`。B 校验 `B0`，下载 `B1` 校验 `50..64` 后追加 `65..99`，再下载 `B2`。最坏浪费 ≤ 一个批次；
- 若 B 先推，边界是 `0..49`、`50..64`；A 之后追加 `65..114`、`115..149`，B 无重叠；
- 复制点落在哪不影响正确性，只影响首次多下载多少（≤ 一个批次）。

### 两种哈希

- **链身份**用批次规范 JSON 的 sha256（比对/分叉判定）；
- **服务端去重**用封装后密文的 sha256（服务端只看到密文，按存储字节寻址）。

manifest 同时记录两种标识：明文 `chainHash` 与密文 `blobSha256`。

## 并发：会话级租约

DSH 的单写者锁只在一台机器内生效，跨机器不拦。服务端按会话发租约：拿到租约才能追加批次；两台同时写同一会话时先到者胜，后来者收到 `409`。

**分叉不自动合并**：`seq`/`surfaceOp`/`sourceEventSeqs` 是格式拥有的关系，重排它们会产出 DSH 读不了的日志。分叉时保留双方，供人工取回。

## 拉取后如何生效

优先走 DSH 原生接缝——`ctx.sessionPersistence.create` / `open(id, 'write')` + `append(events)` 写入，`ctx.workspaceRegistry.resolveByPath` + `Workspace.attachSession` 挂回工作区，避免重启宿主。M0 已验证写入后宿主能发现新会话；已打开的客户端需要 `sessions.refresh()` 才会拉到冷会话。

会话头（`formatVersion`/`createdAt`/`isSeeded`/`delegationDepth`/`agentPreset`，以及 seeded 会话的 `inheritedEventCount`）作为单独的 **sealed header** 上传，manifest 只记哈希；`cwd` 不进入 manifest 明文。拉取端按 `workspaceKey` 的工作区绑定决定落到哪个本地工作区；绑定/映射的加密存储见 [VAULT.md](VAULT.md)。这样同一会话在不同设备上的链身份不受本地路径影响。

开放尾（`tailOpen`/`safeThroughSeq`）、拉取崩溃恢复（apply journal / 启动 reconcile）与客户端防误操作（composer block / 列表拦截）见 [SYNC-SAFETY.md](./SYNC-SAFETY.md)。

## 删除、修复与分叉

会话日志是 append-only，同步协议**没有删除单个事件**的语义：

- **未同步的脏尾**：不上传即可；本地若要彻底干净，用独立的维护操作（备份 → 只保留干净前缀 → 校验 → 原子替换），或走 DSH 的 fork；
- **已同步的脏内容**：不能原地删除；用 **fork 新会话 + 墓碑旧会话**，让两端转向新会话；
- 帧级“复制前缀帧覆盖原文件”只适用于脏内容恰好占满尾帧的情况；一帧可能含多个事件，按帧截断会连带丢掉好事件；
- 修复/导出属于独立维护功能，不参与正常同步链，避免把“可删除”语义带进 append-only 协议。

## 换设备与设备标记

会话在不同设备间继续时，模型需要知道"自己换机器了"。做法：

- 在会话日志里写一条 `plugin:dsh-session-sync/device` 记录（`ignorable`，不进模型可见表面）；
- 用 Session projection 折叠出"最后设备"（不扫历史，`snapshotEvents` 已弃用）；
- 判定为换设备时，在 `agent/pre-step` 追加一条 `<system-reminder>`（最小事实 + 该工作区 agent 笔记摘要），不唤醒会话。

## 加密

默认端到端：口令派生主密钥，按会话派生子密钥，AES-256-GCM 封装每个批次。服务端只知道账户、设备、加密后的会话键、大小与时间。提供一个显式开关"允许服务器解密"（上传包裹后的主密钥），默认关闭；关闭时必须配套密钥轮换，否则旧密文仍可被解开。

封装的字节布局、密钥层次、AAD 与版本规则见 [SEALED-FRAME.md](./SEALED-FRAME.md)（v1 已实现；M3 用它封装事件批次）。

## 服务器形态

本期只做**个人自部署**：单租户、无账号/邮箱，认证是 setup token + 每设备 token。为将来可能的公共部署只保留两个薄接缝：存储的 `dataset` 字段、token 表的 `label`。

## 网页管理台（首版）

自部署服务附带一个只读管理台：浏览器用 setup token 登录，换取 **HttpOnly cookie 会话**；设备 API 仍用 bearer token。管理台**不依赖服务器解密**（默认关闭），首版只做元数据管理：

- 设备 token：签发 / 吊销 / 最后在线；
- 存储：总用量、配额（默认 10 GiB，`--max-bytes` 可配）、按会话统计；
- 会话：id、格式代际、批次数、最后更新、租约持有者、墓碑；
- 系统：健康、协议版本、keybox 状态。

会话内容预览（网页读消息/工具/推理）是 **P2**，依赖“允许服务器解密”：开启后服务端能解**所有历史批次内容**；删除 keybox 不等于收回历史，必须轮换密钥，UI 必须明确警告。

同步 API（`/v1/*`，设备 token）与管理台 API（`/admin/*`，cookie 会话）分开，互不复用认证。

## 首次启动与初始化

服务端首次启动（尚未设置管理密码）时，在控制台打印一次性初始化密钥，并提示打开 `/admin`；浏览器跳到 `/setup` 向导：

1. 输入初始化密钥（8 位、10 分钟有效、单次使用；未完成初始化时每次启动重新生成）；
2. 设置管理密码（≥6 位，字母/数字/特殊字符至少两类；scrypt 加盐哈希，不存明文）；
3. 设置存储配额（默认 10 GiB，之后可在管理台修改）；
4. 可选创建第一台设备（token 只显示一次，可跳过）。

完成后管理台改用密码登录；setup token 只保留给设备 CLI 和 break-glass。忘记密码时执行 `admin reset` 清除密码，重启后重新打印初始化密钥。

## 版本策略

只支持 DSH `>=0.2.1-rc.1 <0.2.2-0`。用**特性探测**而非版本比较；缺必需 API 时装载期报错并给出所需版本。不维护旧版本兼容分支。

## 兼容性边界

同步层只把事件当作不透明 JSON 搬运、不解释事件语义，但**依赖 DSH 能读出并写入这些事件**——未知/不合法事件由 DSH 自己 fail-closed。因此：

- **同一代际**（如 v4）：事件由 DSH 校验；我们按规范 JSON 计算批次哈希，不依赖事件 schema；
- **跨代际**（v4 → v5）：旧 DSH 直接拒读（`sessionFormatVersionRefusal`），同步必须按 `formatVersion` 闸门，不把新代际会话推给旧设备；manifest 与会话台账都记录代际；
- **同代际但 DSH 版本不同**：新补丁若引入旧版不认识的必需事件，旧版读/写会失败；设备台账比较 DSH 版本，默认只向不低于自己的设备推送；
- **物理格式无关**：压缩参数、JSONL/zstd/未来后端都不影响同步；`cwd` 与 header 走带外元数据；
- **插件 API**：`appendPluginRecord` 等只在 `>=0.2.1 <0.2.2` 内验证，越过这个小版本要重新验证；官方校验器随 DSH 升级同步升版本并重跑夹具。

## 非目标

- 不做事件级合并（不重排 `seq`/`surfaceOp`）。
- 不做服务端合并（端到端加密下服务端看不到明文）。
- 不做帧级同步；原始日志导出/恢复（同版本、整文件）是独立的后续功能，不参与同步链。
- 不做原地删除/重写事件；修复走 fork + 墓碑或独立维护操作。
- 不自动重启宿主。
- 第一版不同步工作区项目文件。
