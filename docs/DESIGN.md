# 设计

> 状态：脚手架阶段。范围与关键取舍已定，实现随里程碑推进。

## 目标

把 DSH 的会话数据在自有服务端上做**多设备同步**，默认端到端加密；服务端只保存不透明密文与元数据。

## 数据分三层

| 层 | 内容 | 体量量级 | 冲突性 |
|---|---|---|---|
| L1 会话数据 | `sessions/**`（每会话只取最高格式代际）、`attachments/v1/**`、`storages/workspace.json`、`profiles/*/cordis.patch.yml` + `package.json` | 百 MB 级（取决于历史） | 会话要租约；配置字段级 LWW |
| L2 设备台账 | 每设备一条：OS、DSH 与 profile、已加载插件与版本、会话格式版本、工具链版本与路径、工作区路径、最后在线 | KB 级 | 按 deviceId 分槽，天然无冲突 |
| L3 agent 笔记 | append-only 笔记：设备/会话/工作区/时间/作者/标签 | KB–MB 级 | 只追加，天然无冲突 |

L2 同时是**兼容性闸门**：服务端一次性返回各设备的 `sessionFormatVersion`，同步前就能拒绝代际不匹配的会话。
L3 的工具链条目分 `auto`（自动采集）与 `authored`（agent 或用户维护）两个来源，自动采集**不覆盖** `authored`。

## 传输单位：zstd 帧链

DSH 的会话日志是一串独立 zstd 帧：header 一帧，之后每个持久化批次一帧。已提交帧不可变，只有尾帧可能被崩溃恢复重写。

因此同步单位是**原始帧**：不解码、不重编码、sha256 内容寻址。好处是增量天然成立，而且传输层不可能产出 DSH 读不了的日志。附件本身按 digest 命名，直接按内容寻址同步。

## 并发：会话级租约

DSH 的单写者锁只在一台机器内生效，跨机器不拦。服务端按会话发租约：拿到租约才能追加帧；两台同时写同一会话时先到者胜，后来者收到 `409`。

**分叉不自动合并**：`seq`/`surfaceOp`/`sourceEventSeqs` 是格式拥有的关系，重排它们会产出 DSH 读不了的日志。分叉时保留双方，供人工取回。

## 拉取后如何生效

优先走 DSH 原生接缝——`ctx.sessionPersistence` 写入、`ctx.workspaceRegistry.resolveByPath` + `Workspace.attachSession` 挂回工作区，避免重启宿主。该路径能否让**已打开的客户端**立即看到，是 M0 实验要回答的问题；做不到才回退为提示重启。

## 换设备与设备标记

会话在不同设备间继续时，模型需要知道"自己换机器了"。做法：

- 在会话日志里写一条 `plugin:dsh-session-sync/device` 记录（`ignorable`，不进模型可见表面）；
- 用 Session projection 折叠出"最后设备"（不扫历史，`snapshotEvents` 已弃用）；
- 判定为换设备时，在 `agent/pre-step` 追加一条 `<system-reminder>`（最小事实 + 该工作区 agent 笔记摘要），不唤醒会话。

## 加密

默认端到端：口令派生主密钥，按会话派生子密钥，AES-256-GCM 封装每一帧。服务端只知道账户、设备、加密后的会话键、大小与时间。提供一个显式开关"允许服务器解密"（上传包裹后的主密钥），默认关闭；关闭时必须配套密钥轮换，否则旧密文仍可被解开。

## 服务器形态

本期只做**个人自部署**：单租户、无账号/邮箱、无服务端前端，认证是 setup token + 每设备 token。为将来可能的公共部署只保留两个薄接缝：存储的 `dataset` 字段、token 表的 `label`。

## 版本策略

只支持 DSH `>=0.2.1-rc.1 <0.2.2-0`。用**特性探测**而非版本比较；缺必需 API 时装载期报错并给出所需版本。不维护旧版本兼容分支。

## 非目标

- 不做事件级合并（不重排 `seq`/`surfaceOp`）。
- 不做服务端合并（端到端加密下服务端看不到明文）。
- 不自动重启宿主。
- 第一版不同步工作区项目文件。
