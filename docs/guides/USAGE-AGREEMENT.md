# dsh-session-cloudsync 使用协议（草案）

> 状态：**草案**，随实现更新；不构成法律意见。
> 适用版本：dsh-session-cloudsync 插件与其配套自部署服务端。
> 生效日期：2026-10-21。
> 正式发布前，项目方可以调整本文；发布后以插件包内附带的版本为准。
> 文中术语见 [GLOSSARY.md](GLOSSARY.md)。

## 1. 定位

dsh-session-cloudsync 是 DeepSeek Harness（DSH）的会话同步插件：

- 把本机 DSH 会话同步到你自己部署的服务端，并可拉取到其他设备；
- 默认端到端加密，服务端只保存密文与必要的同步元数据；
- 本插件不管理、不备份、不修改你的项目文件，也不替代 Git 或其他版本控制。

## 2. 本插件修改什么

### 2.1 唯一会修改的会话内容：DSH 必需的 cwd 元数据

为了同步和恢复 DSH 必需的 cwd 元数据，本插件只做以下事情：

1. 会话 header 中的 `cwd`：拉取时使用本地工作区 canonical path 重新创建，而不是保留源设备路径；
2. `working-directory/change` 事件：**原样同步，不转换、不本地化**；
3. 接收端在用户明确确认后，允许在会话末尾 **追加**一条 `working-directory/change`，
   把当前 cwd 修正到本地工作区根；不改写已有事件。

这是本插件**唯一**会写会话数据的地方。它只发生在同步/应用边界；不修改消息、工具调用、
附件或历史事件。

本插件不追求本地会话文件跨设备字节一致，也不承诺整个会话跨平台可用；不做 cwd
canonical 投影，不引入 `@workspace` / `@external`。

> 当前开发版：header cwd 已本地化；接收端追加修正尚未实现，见第 9 节。
> 正式发布版本以实际实现和 release notes 为准。

### 2.2 明确不修改

本插件不会改写、过滤或替换：

- 用户消息、助手消息、推理内容、标题；
- 工具调用的参数、结果、错误、stdout/stderr；
- 附件内容；
- 会话事件的类型、顺序、`seq`、`surfaceOp` 等结构字段；
- 除 DSH 必需 cwd 之外的任何消息或工具调用数据。

如果某个路径无法安全映射（例如工作区之外的目录、未挂载的盘符），本插件不会“猜一个路径”
静默改写；它保留 raw 路径、给出不可移植警告，并在用户确认后允许接收端追加修正。

### 2.3 不自动创建软链或盘符

- `working-directory/change` 原样同步，不依赖本机软链做路径归一化；
- 工作区外路径保留原值并标记 `nonPortable`；不会映射到工作区根；
- 是否创建兼容链接/目录联接由用户显式确认；
- 不会未经同意执行 `subst`、挂载卷或修改系统盘符。

## 3. 用户确认与操作边界

- 工作区映射、同路径自动绑定、兼容链接、版本切换都需要用户可见的操作或确认；
- 默认自动同步普通项（本机新增、远端新增且已映射、前缀一致的单向更新）；
- 冲突、未映射、强行写入分叉才提示用户；
- 打开本地/远端都存在但尚未同步的会话时，插件会拦截输入并提示风险；
  只有勾选“理解强行写入会产生分叉”后才允许本地写入，且不会自动推送/合并；
- 自动绑定只影响“会话落到哪个本地工作区”，不改变会话内容；
- 拉取并 resume 一个来自其他设备/平台的会话前，用户应先确认路径和工具链环境；
- 本插件不静默安装插件版本、不静默升降级 DSH、不静默批准 build script。

## 4. 加密与数据边界

- 同步内容使用口令派生的密钥做端到端加密；
- 服务端可见：设备标识、会话/批次元数据、密文大小、时间、opaque 工作区 key；
- 服务端不可见（默认）：消息、工具调用、cwd、工作区路径、设备台账、agent 笔记；
- 口令或恢复材料丢失后，云端密文无法解密；项目方无法替你恢复；
- 设备 token 和口令由你保管；自部署服务端的安全、备份、访问控制由你负责；
- 如未来提供“允许服务器解密”开关，必须由用户显式开启；当前版本不提供该能力。

## 5. 风险告知

会话同步涉及跨设备写入，存在以下风险，使用前应理解：

1. **分叉**：两台设备同时写同一会话时，协议通过租约避免并发；租约过期、强杀或网络分区
   仍可能产生分叉。分叉不会自动合并，双方内容都会保留，需要人工处理。
2. **开放尾**：正在生成中的会话只备份到安全边界；开放尾不保证可 resume，读者只 apply
   到 `safeThroughSeq`。
3. **路径/环境差异**：另一台设备可能没有相同的工作目录、工具链、插件版本或 DSH 版本；
   恢复后可能出现工作目录恢复、工具不可用或上下文引用旧路径；
   工作区外 cwd 会标记 `nonPortable`，不映射到工作区根，也不保证可 resume；
4. **强行写入**：冲突时勾选风险确认后，本地继续写入会产生分叉；插件不会自动合并，
   也不会把远端内容覆盖到本地；
5. **数据丢失**：任何同步系统都不能替代备份；请保留服务端和本机的独立备份；
6. **未发布版本**：当前插件尚未公开发布，协议、行为和数据结构仍可能变化；
   不要把开发版用于你无法承受丢失的数据。

使用本插件即表示你：

- 对自己的数据、账号、设备、服务端和网络环境拥有合法处理权限；
- 不会用本插件绕过访问控制、窃取他人数据或违反适用法律；
- 会妥善保管 token、口令、恢复材料和自部署服务端；
- 在跨设备 resume 前自行验证工作区、工具链和插件版本；
- 接受“同步不是备份、不能保证零丢失、不能自动解决所有分叉”的事实。

## 9. 开发版补充

截至本文草案：

- header cwd 本地化已实现；`working-directory/change` 保持 raw，未做 cwd canonical 投影；

- 跨平台 resume 仍可能因 raw `working-directory/change` 的绝对路径出现工作目录错误或恢复事件；
- 在实现并验证前，请不要把跨平台 resume 当作稳定能力；
